# 클로드 세션

## 세션이란?

> 대화 기록 하나의 단위

### 세션은 일회용

웹에서 사용하는 클로드인 claude.ai와 달리 Claude Code는 각각의 대화를 기억해두지 않습니다.  
Claude는 시간이 지나도 사용자의 선호도를 "학습"하거나 지난주에 작업한 내용을 기억하지 않습니다.  
새 세션은 항상 처음부터 시작합니다.

### CLAUDE.md

세션 간에 Claude가 알아야 할 내용이 있다면 CLAUDE.md에 넣으면 됩니다.
세션은 항상 CLAUDE.md를 참고합니다.

### 세션은 대화 기록을 저장

- 클로드 코드는 세션의 대화를 **로컬**(내 컴퓨터)에 저장합니다.
- 이를 통해 세션을 **되감기**(이전 상태로 돌아가기), **재개**(중단한 곳에서 다시 시작), **분기**(가지 뻗기)할 수 있습니다.
- 파일 수정 전 원래 내용을 기억해두기 때문에 필요하면 되돌릴 수도 있습니다.

## 세션 재개와 분기

`claude --continue` 또는 `claude --resume`

명령어를 터미널(명령어를 입력하는 검은 화면)에 입력하면 대화를 중단한 지점부터 이어갑니다.

### 세션 분기하기

```bash
claude --continue --fork-session
```

이렇게 하면 해당 시점까지의 대화 기록을 유지하면서 새 세션을 시작할 수 있습니다.

### 여러 터미널에서 동일한 세션 사용

여러 터미널 창에서 동일한 세션을 시작하면 두 창의 메시지가 섞입니다.
동일한 시작점에서 **동시에 여러 작업**을 하려면 `--fork-session`을 사용하여 각 터미널에 고유한 세션을 만드세요.

## 컨텍스트 윈도우(Context Window)

> Claude가 한 번에 기억하고 처리할 수 있는 정보의 양

- 대화 기록
- 파일 내용
- 명령어 실행 결과
- CLAUDE.md 파일
- 로드된 **스킬**(특정 작업을 수행하는 미리 만들어진 기능)
- 시스템 지시사항

`/context` 명령어를 실행하면 무엇이 공간을 차지하고 있는지 볼 수 있습니다.

### 컨텍스트가 가득 찼을 때

Claude Code는 한계에 다다르면 자동으로 컨텍스트를 관리합니다.

1. 먼저 오래된 도구 실행 결과를 지웁니다
2. 필요하면 대화를 요약합니다
3. 사용자의 요청과 주요 코드는 보존됩니다
4. 대화 초반의 상세한 지시사항은 사라질 수 있습니다

그래서 지속적인 규칙은 대화 기록이 아닌 CLAUDE.md에 넣어야 합니다.

### 압축 시 보존할 내용 조작하기

- CLAUDE.md에 "Compact Instructions" 섹션을 추가하거나
- `/compact` 명령어 사용 (예: `/compact focus on the API changes`)

참고: MCP 서버는 상당한 컨텍스트를 소비할 수 있습니다.

## 컨텍스트 공간 절약하기

### 스킬로 최적화

**스킬**: 미리 만들어진 기능 (예: 맞춤법 검사, 문서 요약, 오류 찾기)

**비유: 공구함**

- 공구함에 100개 도구가 있어도 책상 위에는 필요한 것만 꺼냅니다
- 스킬도 마찬가지로 사용할 때만 로드됩니다

**왜 그럴까요?**
Claude의 책상(컨텍스트)은 크기가 정해져 있습니다.
안 쓰는 도구를 모두 올려두면 작업 공간이 없어집니다.

### 서브에이전트로 최적화

**서브에이전트**: 특정 일을 맡아 처리하는 독립적인 Claude -> 독립적인 컨텍스트를 가짐

**비유: 조수에게 일 맡기기**

- 내가 100개 파일을 검토하면 → 내 책상이 자료로 가득 참
- 조수에게 맡기면 → 조수 책상은 가득 차도 내 책상은 깨끗함
- 조수가 일 끝내면 → "문제 3개 발견했어요"라고 요약만 보고

**실제 예시:**

- 대규모 코드 검토 → 서브에이전트가 처리 → 결과만 받음
- 여러 테스트 실행 → 서브에이전트가 처리 → 요약만 받음

긴 대화를 할수록 서브에이전트가 유용합니다.
