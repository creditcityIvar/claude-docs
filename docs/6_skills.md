# Claude Skills

## Skills가 무엇인가요?

Skills는 Claude에게 특정 작업을 어떻게 수행해야 하는지 알려주는 **작업 매뉴얼**입니다.

회사에서 신입 기획자에게 "기획서는 이렇게 작성하세요"라는 가이드를 주는 것처럼, Claude에게 "이 작업은 이렇게 하세요"라고 가르치는 것입니다.

## 왜 필요한가요?

매번 같은 설명을 반복하지 않고, 한 번 만들어두면 계속 사용할 수 있습니다.

**예시:**
- 매주 회의록을 정리할 때마다 "목차는 이렇게, 요약은 이렇게"라고 설명하는 대신
- "회의록 정리" Skill을 만들어두면 자동으로 같은 형식으로 정리됩니다

## Skills의 두 가지 실행 방식

### 1. 자동 실행
Claude가 당신의 요청을 보고 적합한 Skill을 스스로 선택해서 사용합니다.

**예시:**
```
당신: "지난주 회의록 정리해줘"
Claude: (자동으로 '회의록 정리' Skill 활용)
```

### 2. 수동 실행
당신이 직접 명령어로 Skill을 실행합니다.

**예시:**
```
당신: /회의록정리
Claude: (회의록 정리 시작)
```

## Skill 만들기

### 1단계: 폴더 만들기

두 가지 위치 중 선택:

**모든 프로젝트에서 사용**
```
~/.claude/skills/스킬이름/
```

**특정 프로젝트에서만 사용**
```
프로젝트폴더/.claude/skills/스킬이름/
```

### 2단계: SKILL.md 파일 작성

파일은 두 부분으로 구성됩니다.

#### 상단: 기본 정보 (설정)
```yaml
---
name: 회의록정리
description: 회의록을 목차와 액션아이템으로 정리합니다
---
```

#### 하단: 작업 지시사항
```
회의록을 정리할 때는:

1. 맨 위에 회의 일시, 참석자 작성
2. 논의 내용을 주제별로 분류
3. 결정 사항은 별도로 정리
4. 액션 아이템은 담당자와 마감일 포함
```

### 3단계: 사용하기

- 자동: "회의록 정리해줘" (Claude가 자동으로 Skill 사용)
- 수동: `/회의록정리` (직접 명령어 입력)

## 실제 사용 예시

### 예시 1: 기획서 리뷰 Skill

**상황:** 기획서를 작성할 때마다 같은 항목을 체크해야 함

**파일 위치:** `~/.claude/skills/기획서리뷰/SKILL.md`

**내용:**
```yaml
---
name: 기획서리뷰
description: 기획서를 체크리스트로 검토합니다
---

기획서를 리뷰할 때 다음 항목을 확인하세요:

1. **목적**: 왜 이 기능이 필요한지 명확한가?
2. **대상 사용자**: 누가 사용하는지 정의되어 있는가?
3. **성공 지표**: 어떻게 성공을 측정할 것인가?
4. **일정**: 각 단계별 마일스톤이 있는가?
5. **리스크**: 예상되는 문제점과 대응 방안이 있는가?

각 항목별로 통과/미흡/누락을 표시하고, 미흡하거나 누락된 부분은 구체적인 개선 방안을 제시하세요.
```

**사용:**
```
당신: /기획서리뷰
Claude: 기획서를 체크리스트로 검토하고 피드백 제공
```

### 예시 2: 경쟁사 분석 정리 Skill

**상황:** 매달 경쟁사 분석 보고서를 같은 형식으로 정리

**파일 위치:** `.claude/skills/경쟁사분석/SKILL.md`

**내용:**
```yaml
---
name: 경쟁사분석
description: 경쟁사 정보를 분석 보고서 형식으로 정리합니다
---

경쟁사 분석을 다음 형식으로 정리하세요:

## 1. 개요
- 분석 대상
- 분석 기간
- 주요 변화 요약 (3줄)

## 2. 주요 기능 변화
각 경쟁사별로:
- 새로 추가된 기능
- 개선된 기능
- 우리와의 차이점

## 3. 시사점
- 우리가 벤치마킹할 점
- 우리가 차별화할 수 있는 점
- 액션 아이템 (우선순위 포함)

표는 마크다운 형식으로 작성하고, 중요한 부분은 굵게 표시하세요.
```

**사용:**
```
당신: "이번 달 경쟁사 A, B, C의 업데이트 내용 정리해줘"
Claude: (자동으로 경쟁사분석 Skill을 활용하여 정리)
```

### 예시 3: 사용자 피드백 분류 Skill

**상황:** 고객 의견을 기능 요청, 버그, 칭찬 등으로 분류

**파일 위치:** `~/.claude/skills/피드백분류/SKILL.md`

**내용:**
```yaml
---
name: 피드백분류
description: 사용자 피드백을 카테고리별로 분류하고 우선순위를 제안합니다
---

사용자 피드백을 받으면:

1. **카테고리 분류**
   - 기능 요청
   - 버그 리포트
   - UI/UX 개선
   - 칭찬
   - 기타

2. **우선순위 판단** (다음 기준 사용)
   - 긴급: 서비스 사용 불가능
   - 높음: 많은 사용자에게 영향
   - 중간: 일부 사용자에게 영향
   - 낮음: 개선하면 좋음

3. **액션 아이템 제안**
   - 즉시 조치 필요 사항
   - 다음 스프린트 검토 사항
   - 장기 로드맵 반영 사항

결과는 표 형식으로 정리하세요.
```

**사용:**
```
당신: "오늘 받은 고객 의견 20건 분류해줘"
Claude: (자동으로 피드백을 분류하고 우선순위 제안)
```

## Skill의 고급 기능

### 1. 자동 실행 방지

중요한 작업은 실수로 실행되지 않도록 수동으로만 실행되게 설정할 수 있습니다.

```yaml
---
name: 공지발송
description: 전체 사용자에게 공지사항을 발송합니다
disable-model-invocation: true
---
```

이렇게 설정하면 `/공지발송`을 직접 입력해야만 실행됩니다.

### 2. 허용 작업 제한

Skill이 할 수 있는 작업을 제한할 수 있습니다.

```yaml
---
name: 문서검색
allowed-tools: Read, Grep, Glob
---
```

이 설정은 "파일 읽기와 검색만 가능, 파일 수정은 불가"를 의미합니다.

- Read: 문서 읽기
- Grep: 문서에서 특정 단어 찾기
- Glob: 파일 이름으로 찾기

### 3. 최신 정보 자동으로 가져오기

Skill이 실행될 때마다 파일이나 데이터를 자동으로 읽어와서 사용할 수 있습니다.

**무엇이 좋은가요?**

매번 파일을 열어서 복사-붙여넣기 하지 않아도, Skill이 알아서 최신 내용을 가져옵니다.

**예시: 주간 회의록 요약**

매주 금요일에 "이번 주 회의록 요약해줘"라고 요청한다고 가정해봅시다.

**일반적인 방법:**
1. 회의록 파일을 열어서 내용 복사
2. Claude에게 붙여넣기
3. "이걸 요약해줘"라고 요청

**자동으로 가져오는 방법:**

```yaml
---
name: 주간회의록요약
description: 이번 주 회의록을 자동으로 요약합니다
---

## 이번 주 회의 내용
!`cat 회의록.txt`

위 내용을 다음 형식으로 요약하세요:
- 주요 결정 사항 (3개)
- 다음 주 할 일 (담당자 포함)
- 보류된 안건
```

`!`cat 회의록.txt`` 부분이 회의록 파일을 자동으로 읽어옵니다.

**또 다른 예시: 이번 달 매출 보고서**

```yaml
---
name: 월간매출보고
description: 이번 달 매출 데이터를 보고서 형식으로 정리합니다
---

## 이번 달 매출 데이터
!`cat 매출데이터.csv`

위 데이터를 다음 형식으로 정리하세요:
- 총 매출액
- 전월 대비 증감률
- 상위 5개 제품
- 주간별 트렌드 (그래프는 텍스트로)
```

**핵심:**
- `!` 표시가 있으면 "이 파일을 자동으로 읽어와"라는 의미입니다
- 파일이 업데이트되면 항상 최신 내용을 사용합니다
- 복사-붙여넣기 없이 바로 요약/분석할 수 있습니다

**용어 정리:**
- `cat`: 파일 내용을 읽어오는 명령어 (읽기 전용, 파일을 수정하지 않음)

## Skill 파일 구조 정리

### 최소 구성 (필수)
```
스킬이름/
└── SKILL.md
```

### 전체 구성 (선택)
```
스킬이름/
├── SKILL.md          (필수: 메인 파일)
├── README.md         (선택: 설명 문서)
└── examples/         (선택: 예시 파일들)
```

## Skills 위치에 따른 사용 범위

| 위치 | 경로 | 언제 사용되나요? |
|------|------|----------------|
| 개인 | `~/.claude/skills/` | 모든 프로젝트에서 사용 |
| 프로젝트 | `프로젝트/.claude/skills/` | 이 프로젝트에서만 사용 |
| 조직 | 관리자 설정 | 회사 전체에서 사용 |

## 실무 활용 팁

### 1. 자주 하는 작업을 Skill로 만드세요
매주, 매달 반복하는 작업이 있다면 Skill로 만들어두세요.

### 2. 팀원과 공유하세요
좋은 Skill은 프로젝트 폴더에 저장해서 팀원 모두가 사용할 수 있게 하세요.

### 3. 간단하게 시작하세요
처음부터 완벽한 Skill을 만들려고 하지 마세요. 기본 형식만 만들고 사용하면서 개선하세요.

### 4. 명확한 이름을 사용하세요
Skill 이름만 봐도 무슨 일을 하는지 알 수 있게 지으세요.

**좋은 예:** `기획서리뷰`, `회의록정리`, `경쟁사분석`
**나쁜 예:** `작업1`, `도구`, `헬퍼`

## CLAUDE.md와 Skills의 관계

CLAUDE.md 파일이 500줄을 �넘어가면 내용을 Skills로 분리하세요.

**예시:**
- CLAUDE.md: 프로젝트의 핵심 규칙과 가이드
- Skills: 구체적인 작업 방법과 체크리스트

### 각 기능별 비용 비교

Claude는 문서를 읽을 때마다 비용이 발생합니다. 각 기능별로 언제, 무엇을 읽는지가 다릅니다.

| 기능 | 언제 읽나요? | 무엇을 읽나요? | 비용 |
|------|------------|--------------|------|
| CLAUDE.md | 대화를 시작할 때 | 전체 내용 | 높음 (매번 모든 내용을 읽음) |
| Skills | 대화 시작 + 사용할 때 | 시작할 때는 설명만, 사용할 때 전체 내용 | 낮음 (필요할 때만 읽음) |

**쉽게 이해하기:**

CLAUDE.md는 대화를 시작할 때마다 처음부터 끝까지 읽습니다.
- 장점: Claude가 항상 모든 내용을 알고 있음
- 단점: 내용이 많으면 비용이 많이 듦

Skills는 필요할 때만 펼쳐봅니다.
- 장점: 평소에는 제목만 알고 있다가 필요할 때만 읽어서 비용 절약
- 단점: 사용하기 전까지는 상세 내용을 모름

**실무 팁:**

500줄 기준으로 나누세요.
- CLAUDE.md가 500줄 미만: 그냥 CLAUDE.md에 모두 작성
- CLAUDE.md가 500줄 이상: 자주 쓰지 않는 내용은 Skills로 분리

**예시:**

CLAUDE.md (항상 읽힘):
```
- 프로젝트 목표와 핵심 가치
- 문서 작성 기본 원칙
- 브랜드 톤앤매너
- 필수 체크 사항
```

Skills (필요할 때만 읽힘):
```
- 기획서 작성 가이드 (기획서 쓸 때만 필요)
- 경쟁사 분석 템플릿 (분석할 때만 필요)
- 고객 인터뷰 질문지 (인터뷰할 때만 필요)
- 월간 보고서 양식 (보고서 작성할 때만 필요)
```

반복적으로 하는 일을 Skill로 만들면, Claude가 더 효율적으로 일을 도와줄 수 있습니다.
