# 서브에이전트 (Subagent)

## 서브에이전트가 무엇인가요?

> 특정 작업을 맡아 처리하는 **독립적인 Claude 조수**.

Claude에게 복잡한 작업을 시키면, Claude가 혼자 다 하지 않고 전문 조수(서브에이전트)에게 일부를 맡깁니다.
각 조수는 자기만의 작업 공간(컨텍스트)에서 독립적으로 일하고, 결과만 보고합니다.

**비유: 팀 내 전문 담당자에게 일 맡기기**

- 팀장(Claude)이 모든 일을 혼자 하면 → 책상이 자료로 가득 차고 효율이 떨어짐
- 전문 담당자(서브에이전트)에게 맡기면 → 담당자가 알아서 처리하고 결과만 보고
- 팀장의 책상은 깨끗하게 유지됨

## 왜 필요한가요?

### 1. 컨텍스트 절약

Claude의 작업 공간(컨텍스트)은 크기가 정해져 있습니다.

- 내가 100개 파일을 검토하면 → 내 작업 공간이 자료로 가득 참
- 서브에이전트에게 맡기면 → 서브에이전트의 작업 공간만 가득 차고, 내 작업 공간은 깨끗함
- 서브에이전트가 끝나면 → "문제 3개 발견했어요"처럼 요약만 받음

### 2. 병렬 처리

여러 서브에이전트에게 동시에 일을 맡길 수 있습니다.

**예시:**

```
"인증 모듈, 데이터베이스 모듈, API 모듈을 각각 서브에이전트로 조사해줘"
→ 3명의 조수가 동시에 각자의 영역을 조사하고 결과를 종합
```

### 3. 전문화

각 서브에이전트에게 특정 역할과 권한을 부여할 수 있습니다.

- "문서 검토 전문가"에게는 읽기 권한만
- "데이터 분석 전문가"에게는 분석 도구만

### 4. 비용 절약

간단한 작업은 빠르고 저렴한 모델(Haiku)로, 복잡한 작업은 강력한 모델(Sonnet, Opus)로 처리할 수 있습니다.

## 내장 서브에이전트

Claude Code에는 미리 만들어진 서브에이전트가 있습니다. Claude가 상황에 맞게 자동으로 사용합니다.

| 서브에이전트        | 역할             | 할 수 있는 일                       | 사용하는 모델 |
| ------------------- | ---------------- | ----------------------------------- | ------------- |
| **Explore**         | 파일 탐색 전문가 | 파일 찾기, 내용 검색 (읽기만 가능)  | Haiku (빠름)  |
| **Plan**            | 계획 수립 전문가 | 작업 계획을 위한 조사 (읽기만 가능) | 상속          |
| **General-purpose** | 만능 조수        | 조사 + 파일 수정 등 복잡한 작업     | 상속          |

**용어 정리:**

- **상속**: 메인 대화에서 사용 중인 모델을 그대로 사용한다는 뜻

**각 서브에이전트를 쉽게 이해하기:**

- **Explore**: "이 프로젝트에서 로그인 관련 파일이 어디 있는지 찾아봐" → 파일을 찾아서 알려주기만 함
- **Plan**: 계획 모드에서 Claude가 코드를 이해하기 위해 사용. 직접 쓸 일은 거의 없음
- **General-purpose**: "이 파일을 분석하고 문제를 수정해줘" → 조사와 수정 모두 가능

## 서브에이전트가 작동하는 방식

### 자동 위임

Claude가 작업 내용을 보고, 적합한 서브에이전트에게 알아서 맡깁니다.

**예시:**

```
당신: "프로젝트 구조를 파악해줘"
Claude: (자동으로 Explore 서브에이전트에게 위임)
Explore: 파일들을 탐색하고 구조를 정리
Claude: Explore의 결과를 받아서 당신에게 보여줌
```

### 명시적 요청

특정 서브에이전트를 직접 지정할 수도 있습니다.

**예시:**

```
당신: "code-reviewer 서브에이전트로 최근 변경사항을 검토해줘"
Claude: (지정된 서브에이전트에게 위임)
```

### 포그라운드와 백그라운드 실행

서브에이전트는 두 가지 방식으로 실행할 수 있습니다.

**포그라운드 (기본)**

서브에이전트가 끝날 때까지 메인 대화가 멈춥니다.
서브에이전트가 "이거 해도 될까요?" 같은 승인 요청을 하면 당신에게 직접 물어봅니다.

**백그라운드**

서브에이전트가 뒤에서 일하는 동안 당신은 다른 대화를 계속할 수 있습니다.

- 시작 전에 필요한 권한을 미리 요청합니다 (미리 승인받아야 중간에 멈추지 않음)
- 미리 승인받지 못한 작업은 자동으로 거부됩니다
- MCP 도구(외부 서비스 연결)는 백그라운드에서 사용할 수 없습니다

**백그라운드로 실행하는 방법:**

- Claude에게 "이 작업을 백그라운드에서 실행해줘"라고 요청
- 실행 중인 작업을 백그라운드로 보내려면 **Ctrl+B**

백그라운드 서브에이전트가 권한 부족으로 실패하면, 포그라운드로 재개하여 다시 시도할 수 있습니다.

백그라운드 기능을 끄려면 환경 변수 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`을 설정하세요.

## 커스텀 서브에이전트 만들기

내장 서브에이전트 외에 나만의 전문 조수를 만들 수 있습니다.

### 방법 1: `/agents` 명령어 사용 (권장)

Claude Code에서 `/agents`를 입력하면 대화형 인터페이스가 열립니다.

1. `/agents` 입력
2. **Create new agent** 선택
3. 사용 범위 선택 (User-level 또는 Project-level)
4. **Generate with Claude** 선택 후 원하는 서브에이전트 설명 입력
5. 도구와 모델 선택
6. 저장 → 바로 사용 가능 (재시작 불필요)

### 방법 2: 직접 파일 만들기

마크다운 파일을 직접 작성합니다.

**파일 위치:**

- 모든 프로젝트에서 사용: `~/.claude/agents/에이전트이름.md`
- 특정 프로젝트에서만 사용: `프로젝트폴더/.claude/agents/에이전트이름.md`

**파일 구조:**

```yaml
---
name: 에이전트-이름
description: 이 서브에이전트가 하는 일에 대한 설명
tools: Read, Grep, Glob
model: sonnet
---
여기에 서브에이전트의 작업 지시사항을 작성합니다.
어떤 역할인지, 어떻게 일해야 하는지 구체적으로 적어주세요.
```

파일은 두 부분으로 나뉩니다:

#### 상단: 설정 (YAML frontmatter)

```yaml
---
name: 에이전트-이름
description: 언제 이 서브에이전트를 사용해야 하는지 설명
tools: Read, Grep, Glob
model: sonnet
---
```

#### 하단: 작업 지시사항

서브에이전트가 어떻게 일해야 하는지 자세히 적습니다.

### 주요 설정 옵션

| 설정              | 필수   | 설명                                                   |
| ----------------- | ------ | ------------------------------------------------------ |
| `name`            | 예     | 서브에이전트 이름 (영문 소문자, 하이픈 사용)           |
| `description`     | 예     | 언제 이 서브에이전트를 사용할지 설명                   |
| `tools`           | 아니오 | 사용할 수 있는 도구 목록. 생략하면 모든 도구 사용 가능 |
| `disallowedTools` | 아니오 | 사용을 금지할 도구 목록                                |
| `model`           | 아니오 | 사용할 모델 (`haiku`, `sonnet`, `opus`, `inherit`)     |
| `permissionMode`  | 아니오 | 권한 모드 (아래 표 참고)                               |
| `maxTurns`        | 아니오 | 서브에이전트가 작업할 수 있는 최대 횟수                |
| `skills`          | 아니오 | 미리 읽어둘 Skill 목록                                 |
| `mcpServers`      | 아니오 | 연결할 외부 서비스 (Slack, GitHub 등)                  |
| `hooks`           | 아니오 | 서브에이전트 실행 전후에 자동 실행할 명령어            |
| `memory`          | 아니오 | 기억 저장 범위 (`user`, `project`, `local`)            |

**용어 정리:**

- **tools (도구)**: 서브에이전트가 할 수 있는 작업 종류. `Read`는 파일 읽기, `Grep`은 내용 검색, `Glob`은 파일 찾기
- **disallowedTools (금지 도구)**: `tools`에서 특정 도구를 빼고 싶을 때 사용. 예: 모든 도구를 주되 `Write`만 금지
- **model (모델)**: Claude AI의 종류. `haiku`는 빠르고 저렴, `sonnet`은 균형 잡힌 성능, `opus`는 가장 강력
- **permissionMode (권한 모드)**: 서브에이전트가 작업할 때 승인을 어떻게 처리할지 결정
- **maxTurns (최대 턴)**: 서브에이전트가 너무 오래 일하지 않도록 제한하는 설정
- **mcpServers**: Slack, GitHub 등 외부 서비스와 연결하는 설정 (MCP 문서 참고)
- **hooks (훅)**: 서브에이전트가 도구를 사용하기 전/후에 자동으로 실행되는 명령어
- **memory (기억)**: 대화가 끝나도 서브에이전트가 배운 것을 기억하는 기능

#### 권한 모드 (permissionMode)

서브에이전트가 작업할 때 "이거 해도 될까요?"라고 물어보는 방식을 설정합니다.

| 모드                | 동작                                     |
| ------------------- | ---------------------------------------- |
| `default`           | 기본. 필요할 때마다 승인을 요청          |
| `acceptEdits`       | 파일 수정은 자동 승인                    |
| `dontAsk`           | 승인 요청 자동 거부 (허용된 도구만 사용) |
| `bypassPermissions` | 모든 승인 없이 실행 (주의 필요)          |
| `plan`              | 읽기만 가능 (계획 모드)                  |

## 서브에이전트의 기억 (Memory)

서브에이전트는 기본적으로 대화가 끝나면 모든 것을 잊습니다.
`memory` 설정을 켜면, 대화가 끝나도 배운 것을 기억할 수 있습니다.

**비유: 업무 노트를 남기는 담당자**

- memory가 없으면 → 매번 처음부터 다시 파악해야 함
- memory가 있으면 → "지난번에 이런 패턴을 발견했으니 이번에도 확인하자"

### memory 설정 방법

```yaml
---
name: document-reviewer
description: 문서를 검토합니다
memory: user
---
문서를 검토할 때 발견한 패턴과 자주 나오는 문제를 기억에 기록하세요.
다음 검토 시 참고하세요.
```

### memory 저장 범위

| 범위      | 저장 위치                                  | 언제 사용하나요?                                    |
| --------- | ------------------------------------------ | --------------------------------------------------- |
| `user`    | `~/.claude/agent-memory/에이전트이름/`     | 모든 프로젝트에서 기억을 공유하고 싶을 때           |
| `project` | `.claude/agent-memory/에이전트이름/`       | 이 프로젝트에서만 기억하면 될 때 (팀과 공유 가능)   |
| `local`   | `.claude/agent-memory-local/에이전트이름/` | 이 프로젝트에서만, 나만 쓸 때 (Git에 올라가지 않음) |

**어떤 범위를 선택할까요?**

- 잘 모르겠으면 `user`를 추천합니다 (모든 프로젝트에서 활용 가능)
- 프로젝트별 특수한 지식이면 `project` 또는 `local`

### memory가 작동하는 방식

memory를 켜면 서브에이전트의 저장 폴더에 `MEMORY.md` 파일이 생깁니다.

1. 서브에이전트가 작업을 시작하면 `MEMORY.md`를 먼저 읽음
2. 작업 중 새로운 발견이 있으면 `MEMORY.md`에 기록
3. 다음 대화에서 같은 서브에이전트를 사용하면 기록을 참고해서 더 나은 결과를 냄

**실제 활용 예시:**

```
첫 번째 대화:
당신: "document-reviewer로 기획서를 검토해줘"
서브에이전트: 검토 완료. "목적 항목이 자주 누락되는 패턴 발견" → 기억에 저장

두 번째 대화:
당신: "document-reviewer로 새 기획서를 검토해줘"
서브에이전트: 기억을 확인 → "이전에 목적 항목 누락이 많았으니 특히 주의해서 검토"
→ 더 정확한 피드백 제공
```

### memory 활용 팁

- 서브에이전트에게 "작업 전에 기억을 확인해"라고 요청하세요
- 작업 후에는 "배운 것을 기억에 저장해"라고 요청하세요
- `MEMORY.md`는 200줄 이하로 유지하는 것이 좋습니다 (너무 길면 읽는 데 비용이 듦)

## 실제 사용 예시

### 예시 1: 문서 검토 서브에이전트

기획서나 보고서를 수정 없이 검토만 하는 읽기 전용 서브에이전트입니다. `tools`에서 Write와 Edit를 제외해 실수로 파일을 수정하는 것을 방지합니다.

```markdown
---
name: document-reviewer
description: 문서 검토 전문가. 기획서, 보고서 작성 후 즉시 검토할 때 사용하세요.
tools: Read, Grep, Glob
model: sonnet
---

당신은 문서 검토 전문가입니다.

호출되면:

1. 요청받은 문서를 읽기
2. 아래 체크리스트로 검토 시작

검토 체크리스트:

- 문서의 목적이 명확한가?
- 대상 독자가 정의되어 있는가?
- 논리적인 순서로 구성되어 있는가?
- 빠진 내용이 없는가?
- 모호한 표현이 없는가?
- 수치나 근거 자료가 포함되어 있는가?

피드백은 우선순위별로 정리하세요:

- 필수 수정 (반드시 고쳐야 할 부분)
- 권장 수정 (고치면 좋을 부분)
- 제안 (참고할 만한 개선 아이디어)

각 항목에 구체적인 개선 방안을 포함하세요.
```

### 예시 2: 자료 조사 서브에이전트

경쟁사 분석이나 시장 조사를 할 때 자료를 수집하고 정리하는 서브에이전트입니다. WebSearch와 WebFetch 도구를 포함해 웹 검색이 가능합니다.

```markdown
---
name: researcher
description: 자료 조사 전문가. 경쟁사 분석, 시장 조사, 트렌드 파악 시 사용하세요.
tools: Read, Grep, Glob, WebSearch, WebFetch
model: sonnet
---

당신은 자료 조사 전문가입니다.

호출되면:

1. 조사 대상과 범위를 파악
2. 관련 자료를 탐색하고 수집
3. 핵심 내용을 분석
4. 보고서 형식으로 정리

핵심 원칙:

- 출처를 반드시 명시
- 사실과 의견을 구분
- 수치 데이터를 우선 수집
- 최신 정보 위주로 조사

조사 결과는 다음 형식으로 정리하세요:

- 요약 (3줄 이내)
- 주요 발견 사항 (3-5개, 근거 포함)
- 시사점 (우리에게 미치는 영향)
- 추가 조사가 필요한 부분
```

### 예시 3: 데이터 정리 서브에이전트

CSV나 엑셀 데이터를 분석하고 보고서로 정리하는 서브에이전트입니다. Bash 도구로 데이터를 처리하고, Write로 보고서 파일을 생성합니다.

```markdown
---
name: data-organizer
description: 데이터 분석 전문가. 매출 데이터, 사용자 통계 등을 보고서로 정리할 때 사용하세요.
tools: Read, Bash, Write
model: sonnet
---

당신은 데이터 정리 전문가입니다.

호출되면:

1. 데이터 파일을 읽고 전체 구조 파악
2. 핵심 수치 계산 (합계, 평균, 증감률 등)
3. 이상치나 특이 패턴 확인
4. 보고서 형식으로 정리

핵심 원칙:

- 원본 데이터를 수정하지 않음
- 계산 과정을 명시
- 전월/전년 대비 비교 포함
- 표와 목록을 활용해 가독성 확보

보고서는 다음 형식으로 작성하세요:

- 요약 (3줄 이내)
- 주요 수치 (표 형식)
- 특이 사항 (이상치, 급변동)
- 시사점 및 제안
```

## 서브에이전트 위치에 따른 사용 범위

| 위치     | 경로                       | 언제 사용되나요?       |
| -------- | -------------------------- | ---------------------- |
| 개인     | `~/.claude/agents/`        | 모든 프로젝트에서 사용 |
| 프로젝트 | `프로젝트/.claude/agents/` | 이 프로젝트에서만 사용 |

**팁:**

- 나만 쓰는 서브에이전트 → 개인 위치에 저장
- 팀원과 함께 쓰는 서브에이전트 → 프로젝트 위치에 저장 (Git으로 공유 가능)

## Skills와 서브에이전트의 차이

**Skills**는 "작업 매뉴얼"입니다. Claude에게 특정 작업을 어떻게 해야 하는지 알려줍니다.

**서브에이전트**는 "전문 담당자"입니다. 독립된 작업 공간에서 일을 처리하고 결과만 보고합니다.

| 비교 항목       | Skills                  | 서브에이전트              |
| --------------- | ----------------------- | ------------------------- |
| **비유**        | 작업 매뉴얼             | 전문 담당자               |
| **작업 공간**   | 메인 대화에서 실행      | 독립된 작업 공간에서 실행 |
| **컨텍스트**    | 메인 대화의 공간을 사용 | 별도의 공간을 사용 (절약) |
| **적합한 상황** | 반복적인 작업 형식 통일 | 대량 작업 처리, 병렬 조사 |
| **결과**        | 메인 대화에 직접 표시   | 요약만 메인 대화로 전달   |

**함께 쓸 수도 있습니다:**

서브에이전트에 Skills를 연결하면, 전문 담당자에게 작업 매뉴얼을 미리 주는 것과 같습니다.

```yaml
---
name: report-writer
description: 보고서를 작성합니다
skills:
  - 보고서양식
  - 문서작성규칙
---
```

## 서브에이전트의 기억 (Memory)

서브에이전트는 기본적으로 대화가 끝나면 모든 것을 잊습니다.
`memory` 설정을 켜면, 대화가 끝나도 배운 것을 기억할 수 있습니다.

**비유: 업무 노트를 남기는 담당자**

- memory가 없으면 → 매번 처음부터 다시 파악해야 함
- memory가 있으면 → "지난번에 이런 패턴을 발견했으니 이번에도 확인하자"

### memory 설정 방법

```yaml
---
name: document-reviewer
description: 문서를 검토합니다
memory: user
---
문서를 검토할 때 발견한 패턴과 자주 나오는 문제를 기억에 기록하세요.
다음 검토 시 참고하세요.
```

### memory 저장 범위

| 범위      | 저장 위치                                  | 언제 사용하나요?                                    |
| --------- | ------------------------------------------ | --------------------------------------------------- |
| `user`    | `~/.claude/agent-memory/에이전트이름/`     | 모든 프로젝트에서 기억을 공유하고 싶을 때           |
| `project` | `.claude/agent-memory/에이전트이름/`       | 이 프로젝트에서만 기억하면 될 때 (팀과 공유 가능)   |
| `local`   | `.claude/agent-memory-local/에이전트이름/` | 이 프로젝트에서만, 나만 쓸 때 (Git에 올라가지 않음) |

**어떤 범위를 선택할까요?**

- 잘 모르겠으면 `user`를 추천합니다 (모든 프로젝트에서 활용 가능)
- 프로젝트별 특수한 지식이면 `project` 또는 `local`

### memory가 작동하는 방식

memory를 켜면 서브에이전트의 저장 폴더에 `MEMORY.md` 파일이 생깁니다.

1. 서브에이전트가 작업을 시작하면 `MEMORY.md`를 먼저 읽음
2. 작업 중 새로운 발견이 있으면 `MEMORY.md`에 기록
3. 다음 대화에서 같은 서브에이전트를 사용하면 기록을 참고해서 더 나은 결과를 냄

**실제 활용 예시:**

```
첫 번째 대화:
당신: "document-reviewer로 기획서를 검토해줘"
서브에이전트: 검토 완료. "목적 항목이 자주 누락되는 패턴 발견" → 기억에 저장

두 번째 대화:
당신: "document-reviewer로 새 기획서를 검토해줘"
서브에이전트: 기억을 확인 → "이전에 목적 항목 누락이 많았으니 특히 주의해서 검토"
→ 더 정확한 피드백 제공
```

### memory 활용 팁

- 서브에이전트에게 "작업 전에 기억을 확인해"라고 요청하세요
- 작업 후에는 "배운 것을 기억에 저장해"라고 요청하세요
- `MEMORY.md`는 200줄 이하로 유지하는 것이 좋습니다 (너무 길면 읽는 데 비용이 듦)

## 실무 활용 팁

### 대량 작업 격리

서브에이전트의 가장 효과적인 사용법입니다.
많은 파일 검토, 긴 로그 분석 등 결과가 방대한 작업을 서브에이전트에게 맡기면, 상세한 내용은 서브에이전트의 컨텍스트에만 남고 요약만 메인 대화로 돌아옵니다.

```
"서브에이전트로 전체 문서를 검토하고 문제가 있는 부분만 알려줘"
```

### 병렬 조사

서로 독립적인 조사는 여러 서브에이전트를 동시에 띄워 처리할 수 있습니다.

```
"인증 모듈, 데이터베이스 모듈, API 모듈을 각각 서브에이전트로 조사해줘"
→ 3명의 조수가 동시에 각자의 영역을 조사하고 결과를 종합
```

각 서브에이전트가 독립적으로 조사한 뒤, Claude가 결과를 종합합니다.

> 주의: 서브에이전트가 끝나면 결과가 메인 대화로 돌아옵니다. 너무 많은 서브에이전트를 동시에 돌리면 결과만으로도 컨텍스트가 차올 수 있습니다.

### 순차 연결 (체이닝)

여러 단계의 작업을 서브에이전트를 순서대로 호출해 처리할 수 있습니다.
각 서브에이전트가 작업을 끝내면 결과를 Claude에게 반환하고, Claude가 다음 서브에이전트에게 전달합니다.

```
"document-reviewer로 기획서의 문제를 찾고, 그 다음 report-writer로 수정해줘"
→ Claude가 순서대로 각 서브에이전트를 호출
```

> 서브에이전트는 다른 서브에이전트를 직접 호출할 수 없습니다. 반드시 메인 Claude를 통해 순서대로 연결해야 합니다.

### 서브에이전트 재개

서브에이전트가 끝난 뒤에도 이어서 작업할 수 있습니다.
재개된 서브에이전트는 이전 작업 내용을 모두 기억하고 있어 처음부터 다시 시작하지 않습니다.

```
당신: "document-reviewer로 기획서 1장을 검토해줘"
(서브에이전트 완료)

당신: "아까 검토를 이어서, 2장도 검토해줘"
(Claude가 같은 서브에이전트를 재개 → 1장 검토 내용을 기억한 채 2장 검토)
```

### 메인 대화 vs 서브에이전트 선택 기준

| 상황                               | 추천         |
| ---------------------------------- | ------------ |
| 왔다 갔다 대화하며 수정해야 할 때  | 메인 대화    |
| 빠르게 간단한 수정을 할 때         | 메인 대화    |
| 여러 단계가 같은 맥락을 공유할 때  | 메인 대화    |
| 결과가 많이 나오는 작업            | 서브에이전트 |
| 도구 권한을 제한하고 싶을 때       | 서브에이전트 |
| 작업이 독립적이고 요약만 필요할 때 | 서브에이전트 |

### 명확한 이름과 설명 작성

Claude는 `description`을 보고 언제 서브에이전트를 사용할지 판단합니다.

**좋은 예:** `description: 기획서를 체크리스트로 검토합니다. 기획서 리뷰 시 사용하세요.`
**나쁜 예:** `description: 문서 작업`

### 필요한 도구만 허용

검토만 하는 서브에이전트에게 파일 수정 권한을 줄 필요가 없습니다.
`tools`에 필요한 것만 적으면 실수를 방지할 수 있습니다.

### 긴 대화일수록 서브에이전트 활용

대화가 길어지면 컨텍스트가 점점 차오릅니다.
서브에이전트를 활용하면 공간을 절약할 수 있습니다.
